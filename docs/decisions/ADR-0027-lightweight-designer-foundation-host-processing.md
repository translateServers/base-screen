# ADR-0027：轻量设计器基座与宿主重型处理边界

> 状态：已接受
> 日期：2026-08-10
> 部分取代：[ADR-0017](./ADR-0017-designer-product-host-boundaries.md)
> 关联：[ADR-0010](./ADR-0010-host-resource-deadline-and-blueprint-runtime.md)、[ADR-0012](./ADR-0012-designer-project-lifecycle.md)、[ADR-0018](./ADR-0018-host-intents-assets-and-graph-blueprint.md)、[ADR-0082](./ADR-0082-dataset-consumption-contract.md)
> 范围影响：[已归档 Designer Full Product](../specs/archive/designer-full-product/spec.md)

## 1. 背景

Base Screen 已经通过 canonical document、Host Adapter 和资源 intent 隔离了凭证与真实数据执行，但产品规划仍把
项目目录、发布、快照、资产和完整业务工作流列为 Designer 自身的建设目标。这会让一个可嵌入基座逐步承担宿主
应用外壳、业务编排和后端能力，并持续扩大公共 API、依赖、运行时状态与交付成本。

用户于 2026-08-10 明确将项目定调为“轻量的大屏设计器基座”，重型处理由宿主负责。本 ADR 将该方向转化为可用于
需求准入、代码评审和包边界检查的长期规则。

## 2. 决策

### 2.1 产品定位

Base Screen 是轻量、可嵌入、跨框架的大屏设计器基座，不是完整的大屏业务应用、项目管理产品或后端平台。

“轻量”约束的是职责、依赖和运行时所有权，不降低本地作者体验的正确性要求。Base Screen 继续拥有高质量的文档
编辑、画布交互、历史、渲染、物料协议和诊断；它不拥有这些能力背后的业务系统和重型执行设施。

### 2.2 所有权

| Base Screen 拥有 | 宿主拥有 |
| --- | --- |
| Canonical Document、严格解析、序列化与诊断 | 项目实际存储、目录、搜索、版本、租户与业务元数据 |
| 本地命令、事务、历史、选择、几何、画布与检查器 | 认证、授权、审计、路由、业务 Store 与页面工作流 |
| Viewer/Designer 渲染、Material ABI 与实例级目录 | 数据查询、聚合、分页、轮询、缓存、ETL 与跨组件共享 |
| 有界的 capability 检查、请求取消、deadline、generation guard 与结果投影 | 资产上传、存储、转码、压缩、缩略图和大文件传输 |
| JSON-safe intent、port、Custom Element method 与 CustomEvent 契约 | 发布、部署、公开 URL、截图、视频、批量导出和其他长任务 |

Base Screen 可以发起与当前设计会话直接相关的有界请求，例如 load、save、publish、资源解析或 host action，也可以
显示其状态；请求的真实执行、业务决策和持久化始终属于宿主。Base Screen 不提供隐式本地后端、通用网络客户端、
任务队列或宿主能力缺失时的业务降级实现。

### 2.3 重型处理判定

满足以下任一条件的能力默认属于宿主：

- 需要账号、租户、凭证、业务权限或服务端审计。
- 依赖跨项目、跨实例或跨用户的共享状态。
- 处理规模不受当前文档与既有 JSON budget 明确约束的数据、文件或计算。
- 需要后台调度、队列、持久缓存、长轮询、分布式重试或长任务进度恢复。
- 实现取决于特定数据平台、存储、部署系统或业务领域模型。

Base Screen 对这类能力最多定义最小意图和有界结果契约，并负责取消、超时、迟到结果保护与安全展示。它不实现
实际处理，也不把宿主服务对象、任意 callback、URL、SQL、凭证或传输配置带入 document 和公共运行时状态。

### 2.4 范围准入

- 新功能必须先证明它是可移植作者内核、渲染内核或必要的宿主边界；“完整产品会有”不是进入 Base Screen 的理由。
- 能通过现有 port、intent、method 或 event 交给宿主完成的重型能力，不新增 Base Screen 内部实现或 package。
- Engine 可以提供当前会话所需的轻量调用入口和反馈，但不扩展为项目中心、发布中心、资产后台或数据工作台。
- 新增第三方生产依赖必须直接改善基座核心能力，并继续满足既有依赖准入、体积、隔离与可移除性门禁。
- 任何把宿主职责迁回 Base Screen 的提案都必须由新的已接受 ADR 明确取代本决策，并由生效中的 Spec 验收。

## 3. 对既有决策与规格的影响

- ADR-0017 中 Host Adapter 的 capability、取消、revision、generation guard、错误脱敏和 fail-closed 规则继续有效。
- ADR-0017 将项目目录、搜索、筛选、克隆、删除、完整发布、快照和恢复作为 Base Screen 产品建设目标的部分被取代；
  这些工作流由宿主组合，Base Screen 只保留必要的会话级契约与调用能力。
- ADR-0018、ADR-0023 和 ADR-0026 的 intent、纯计算、表单作者与宿主执行边界符合本决策，继续有效。
- `Designer Full Product` 中尚未完成的全产品扩展不再授权实现，按原勾选状态归档。画布精度、事件管控、主题、
  数据绑定和事件 Blueprint 等聚焦于本地作者内核或有界宿主端口的独立 Spec 可继续实施。
- 本决策不要求在无迁移 Spec 的情况下删除已经发布的公共端口或现有轻量会话 UI；后续只能修复其正确性、质量和
  安全边界，不得以兼容维护为由继续扩展成宿主产品壳。

## 4. 排除方案

- 在 Engine 中继续补齐完整项目、资产、数据和发布后台：拒绝，会将基座变成特定宿主产品。
- 为每种宿主系统新增专用 package 或传输配置：拒绝，会扩大固定包图并泄露业务模型。
- 只提供一个可注入任意函数或服务对象的逃生口：拒绝，无法验证、序列化、取消、限权或审计。
- 因“轻量”删除本地编辑质量、确定性、安全限制或浏览器验收：拒绝，轻量是职责收敛，不是降低工程标准。

# Designer 持续质量治理计划

> 状态：规划中
> 日期：2026-08-30
> 前序：[DataV 高保真右侧检查器改造方案](../archive/datav-inspired-designer-uiux/plan.md)
> 定位：持续证明 UI 质量与架构边界，不扩大 Base Screen 产品范围

## 目标

在 P0–P14 已完成聚合文件拆分、目录治理和历史文件规模基线清零的基础上，把现有架构边界、
无抖动要求、可访问性、性能预算和测试目标线转化为可重复执行的自动证据。

本计划只承载工程质量治理。若阶段工作需要改变公共契约、产品边界或宿主职责，必须先建立对应
ADR 与增量 Spec，不得由本计划直接授权范围扩展。

## 治理阶段

1. **P15：子层依赖自动化。** 把 `controllers/layers`、`dom/panel`、`designer-element`、renderer 运行时、
   contract validators 的允许依赖编码进现有边界脚本；增加循环与反向导入测试。退出条件是目录语义可由
   CI 证明，而不只依赖评审记忆。
2. **P16：无抖动几何回归。** 在 1024 × 640 和桌面视口中记录 hover、focus、选择、主题、数据刷新、
   面板折叠前后的关键 bounding box 与滚动轨道；覆盖字体/图片延迟和 overlay 打开关闭。退出条件是几何
   变化仅来自显式状态或动画，稳定状态零意外位移。
3. **P17：可访问性工作流矩阵。** 覆盖功能轨、图层树、检查器、颜色面板、数据步骤与命令面板的 Tab
   顺序、焦点恢复、ARIA 数值/关系、高对比和减少动画偏好；把鼠标场景逐项配对为键盘场景。
4. **P18：大文档性能预算。** 为高组件数、深图层、长物料目录和连续数据刷新建立可重复 benchmark，记录
   render/mutation 次数、长任务和内存回收基线，再以实测值建立 ratchet；不在 Engine 引入持久缓存或后台
   队列。
5. **P19：样式与 Token 收敛。** 审计重复色值、间距、层级和 z-index，补齐稳定滚动轨道与 overlay 层级
   清单；保持每个装配域唯一入口和 style node 原子更新。
6. **P20：测试职责治理。** 按可观察行为和状态机边界组织测试；仅当场景能独立命名、准备和失败时拆分，
   fixture 只暴露最小场景 API。测试聚焦自定义校验、事务、取消与状态转换，不增加重复框架默认行为的
   断言，也不为满足行数目标打散同一行为链。

## 执行与验收

- 每一阶段先冻结可观察行为、最小接口和失败口径，再修改实现与测试。
- 阶段内运行聚焦检查；阶段退出运行 `pnpm verify:fast`，涉及视觉或交互时追加
  `pnpm verify:browser`，交付批次最终运行 `pnpm verify:m0`。
- 1024 × 640 最小设计器尺寸与桌面视口均不得出现非预期遮挡、滚动轨道跳变或稳定几何位移。
- 鼠标工作流必须有对应键盘路径；焦点恢复、ARIA 关系、高对比和减少动画偏好均进入验收矩阵。
- 文档修改继续只经过 Core transaction/history；宿主能力继续只通过公开、JSON-safe 的请求、端口、
  方法或事件接入。
- 每个阶段完成后更新本计划的证据与状态；全部阶段完成后将本计划移入归档，不把已完成任务长期留在
  活动计划索引中。

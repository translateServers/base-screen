# 智能体全链路测试与样式评审（2026-10-30）

> 目的：把「智能体」这一条链路当成产品完整走一遍——从一句话到大屏落库、到设计器提案、到采纳保存、
> 到三端渲染与探针，全部页面**由大模型产出**，过程中记录卡点与样式缺陷。
> 环境：Windows 11 + Node 22.22.2，共享后端 3000（`node dist/main.js`），vanilla / react / vue 宿主 5173/5174/5175，
> 模型 `deepseek-v4.1-flash`（`examples/shared-backend/.env.local`）。
> 基线：`efab848`，工作区另有 11 个未提交改动（`designer-change-dom.ts`、workbench CSS、三端 layout/online-materials CSS 等），
> 本次测试在**当前工作区**上跑，未改动任何源码。

---

## 1. 结论先行

链路是通的：20 次模型调用、6 张 LLM 大屏、6 张屏在三端渲染零对比度违规、设计器提案能采纳能保存、
MCP 12 个工具冒烟通过。但**「能用」和「好用」之间隔着一整层**，最要紧的三条：

1. **幽灵草案把新旧内容叠在一起画**。整屏候选时新旧两套文字直接重叠，标题变成「销售运营履约监控」这种字面叠加物；
   单组件候选时同一标题在 DOM 里同时存在 46px 与 64px 两份。所谓「对比预览」只是把候选 `display:none`，不是 diff。
   → 评审面不可用，而这是报告二六态里最核心的 S3/S5 一环。
2. **单条采纳会把文档拆坏**。整屏替换被拆成 78 个变更单元，其中第一单元是「删除旧组件」。只点这一条，文档从 6 个组件掉到
   1 个，而画布仍显示 77 个幽灵组件——用户看到的和落盘的不是一个东西。
3. **兜底产物把假数字画进主视觉**。6 张里 2 张因超时退回确定性兜底，产出「总量 35.5 万 / 周转 23.7 天 / 缺货 15 家」这种
   与主题无关、但看起来像真实经营数据的屏；标题还被截成「双十一大促作战室：支」。

样式层面上，LLM 的**内容**已经合格（有口径、有结构、有数据），坏的是**编译器给它的版式**：等宽四栏、固定 556px 面板、
从 0 归一导致 PUE 七根柱几乎等高、12px 轴标签占文本节点一半、屏底 172px 死角、图片永远空白。

## 3. 链路结果

### 3.1 六个主题，全部由模型生成

| 主题 | mode | 耗时 | 组件 | 指标卡 | 面板 | 探针 TTV | 对比度违规 |
|---|---|---|---|---|---|---|---|
| 全国冷链干线运输实时监控 | llm | — | 77 | 4 | 走势 / 在途 / 处置清单 / 现场图 | 666ms | 0 |
| 双十一大促作战室 | **deterministic** | — | 52 | 4 | 兜底三件套 | 567ms | 0 |
| 城市轨道交通客流调度 | llm | 10.5s | 77 | 4 | 分时客流 / 拥挤指数 / 调度清单 / 现场 | 563ms | 0 |
| 三甲医院门诊运营 | llm | 21.1s | 84 | 5 | 候诊人数 / 门诊量 / 压力清单 / 现场 | 596ms | 0 |
| 集团财务月度经营分析 | **deterministic** | 25.0s 超时 | 52 | 4 | 兜底三件套 | 559ms | 0 |
| 数据中心能耗与 PUE | llm | 12.5s | 59 | 5 | PUE 趋势 / 能耗清单 / 冷站画面 | 572ms | 0 |

三端一致性（同一张 UI 链路屏）：vanilla 53 个文本节点、react 53、vue 53；对比度 / 字号违规均 0；TTV 619–686ms。

### 3.2 模型调用的可靠性

20 次真实调用里：

- **2 次 25s 超时**（`AGENT_UNREACHABLE`）——正好卡在 `agent-client.ts` 的 `DEFAULT_TIMEOUT_MS = 25_000`；门诊那次 21.1s 已贴着上限；
- **2 次上游 400**（`AGENT_HTTP_400`），都发生在组件级编修；
- **1 次结构拒绝**（`AGENT_SPEC_INVALID`，见 3.4 负值）；
- 成功调用耗时 2.9s / 5.0s / 8.3s / 10.5s / 12.5s / 13.9s / 14.1s / 15.8s / 21.1s。

客户端只有「一次请求 + 超时即放弃」，没有重试、没有流式、没有降级重试策略。命中超时的结果就是兜底，
而兜底在这里不是「次优解」，是「错解」（见 3.5）。

### 3.3 设计器「智能体」页签

| 步骤 | 结果 |
|---|---|
| 空态 | 三张起点牌（从指标 / 从模板 / 从一句话）都在 |
| 提交整屏意图 | 先弹「确认整屏作用域」（77ms），确认后才发请求 |
| 提案到达 | **5.0s**（LLM 正常时），78 个变更单元 |
| 采纳全部 | 文档 6 → 77 组件，待决清空 |
| 保存（顶栏「保存」） | revision 1 → 2，落库 77 组件 ✅ |
| 组件级 patch | 2.9s，1 个单元：「面板标题 · 数据源 常量 · 各区域库存水位 → 常量 · 华东仓网库存水位」✅ |
| 数值意图「字号改成 64」 | **没有任何变更**，字号仍 40（见 4.6） |
| Esc × 2 | **待决草案没消失**（`readPendingChange()` 仍为 true） |

两个硬伤：

**（a）单条采纳把文档拆坏。** 78 个单元是 1 条「删除旧组件」+ 76 条「新增组件」+ 画布。
先采纳删除那一条，文档立刻从 6 个组件变成 1 个，而画布上仍然是完整的幽灵预览：

```text
adopt-one  doc{before: 6 components, pending}  →  doc{after: 1 component, pending}
底部状态栏：1 个组件     画布：77 个幽灵组件      ← 二者矛盾
```

此时若保存 / 预览 / 关页，得到的是只剩背景的屏。删除与新增不是原子组，也不保证顺序。

**（b）78 条单元没法评审。** 每行都是「背景 / 新增 / 忽略此项 / 采纳此项」，13 个「柱」、13 个「柱值」、13 个「X 轴」，
用户唯一的现实选择是「全部采纳」。整屏替换本应是一个可整体接受/拒绝的单元，附一份可展开的组件清单。

### 3.4 边界与失败路径

| 用例 | 结果 | 评价 |
|---|---|---|
| 空主题 | 400 `topic must be longer than or equal to 2 characters` | 后端拦住了 |
| 仅空格 | 放行到模型 → `AGENT_HTTP_400` → 兜底「示例大屏」 | 校验不 trim，前端可绕过 |
| 123 字需求（3 句） | 400，界面显示英文 `topic must be shorter than or equal to 120 characters` + 「重试」 | **重试必然再失败**（见 4.7） |
| 要求「有正有负的同比」 | `AGENT_SPEC_INVALID` → 兜底编造库存数字 | 负值整份拒绝（见 4.4） |
| 要求地图 / 仪表盘 / 漏斗 | 模型给「全国转化漏斗」→ 编译器画成柱状图，无任何提示 | 静默降级 |
| 注入式指令（「不要 JSON」） | 模型仍返回合法 spec，产出正常屏 | 抗注入 OK |
| emoji / `<script>` | 正常，未被注入 | OK |
| 纯英文主题 | 产出全中文屏（模型翻译） | 语言不跟随 |

### 3.5 兜底产物的问题

财务屏（超时兜底）实际渲染成：

- 指标卡：**总量 35.5 万 / 周转 23.7 天 / 缺货 15 家 / 在途 3415 万** —— 全部是库存口径，与「集团财务月度经营」无关；
- 数值是主题哈希生成的**确定但虚构**的数，视觉上与真实经营数据无从区分；
- 清单写「· 集团财务月度经营分析·指标口径待确认 / 数据源待接入 / 明细维度待补齐」——把内部待办画进了大屏；
- 唯一声明是副标题一行 20px 灰字「示例智能体的确定性兜底 · 未调用模型」，在 3m 外不可读；
- 列表名「双十一大促作战室：支」——`subject.slice(0, 10)` 从词中间切断。

诚实标注这件事做对了一半（接口 `mode`/`failure` 如实返回），但**产物本身不该长这样**：
兜底要么产出空态（「等待重试」），要么只给结构不给数字，不能给一套像真的一样的假数。

### 3.6 工具面与快照

- `screen-mcp-server` 冒烟：3 resources / 12 tools 通过。
- 导出：`export-host-screen --screen <id>` 成功，但日志带 `[migrated]`。
  对比发现 **智能体产物写的是 legacy 字段**：

```text
产物           dataSource: { type: "static", value: "…" }
导出/加载后    dataSource: null, dataValue: { kind: "inline", value: "…" }
```

  也就是说新生成的大屏每次加载都要跑一次迁移，同一张屏在「生成 → 保存」之间会切换两种取值形态。
- `fit_resolution` 到 1366×768：`scale 0.71`、`belowMinComponentPx.count = 0`——它按**组件尺寸**判定，
  不感知字号，12px 轴标签缩到 8.5px 依然算通过。

### 3.7 另一条入口：宿主专属设计 Skill

智能体还有一条「离线」入口——宿主生成 `design-<hostId>-screens`，让任意模型按宿主物料产出可导入的文档。
这条链路的生成器本身有覆盖（`npx vitest run tests/host-skills` → 4 文件 / 46 通过），但**仓库里没有可运行的样例**：
两个生成器与物料 MCP 都要求 `.base-screen/host-snapshot.json`，示例宿主不产出它，也没有 fixture。后果是

```text
$ node tooling/material-mcp-server/smoke.mjs
McpError: MCP error -32000: Connection closed
# 服务端真因：ENOENT: no such file or directory, stat '…/.base-screen/host-snapshot.json'
```

服务端遇到缺文件直接进程退出，客户端只看到「连接关闭」，没有任何结构化诊断码。这条路径当前无法自检，
也不在 `verify:m0` 里。

## 4. 样式评审

评审对象：6 张 LLM 屏 + 1 张设计器链路屏，1920×1080 / 2560×1440 / 1366×768 三档。
截图在 `.base-screen/local/scratch/agent-e2e-2026-10-30/shots/`。

### 4.1 版式：等宽四栏是万用模板，不是设计

`agent-compose.ts` 把面板宽度写成 `(1920 - 128 - 24×(n-1)) / n`，高度固定 556。于是：

- **内容密度完全错配**：图表面板被挤到 ~330px（7 根柱 + 数值 + 轴标签挤在一起），清单面板只有 3–5 行却占同样宽度，
  下方 2/3 是空的（冷链、门诊、地铁三张都这样）；
- **3 个面板时右侧直接缺一块**，4 个面板时图片栏永远是最空的那一栏；
- **屏底 172px 死角**：所有屏内容底边都停在 y=908，页脚在 944，970→1080 完全空白。

LLM 其实给出了「主次」信息（面板标题、note、数据量），编译器一条都没用上。

### 4.2 图片面板永远是黑洞

每张屏 1 个 `base.image`，URL 是 `https://picsum.photos/seed/…`。本机网络下加载失败：

```text
console: Failed to load resource: net::ERR_PROXY_CONNECTION_FAILED
```

结果是大屏里 1/4（4 面板时）或 1/3（3 面板时）的区域**纯黑，无占位、无 loading、无兜底底板**。
内网大屏场景下这不是偶发，是必然。且方向与 ADR-0089 相反：图片应走 `host-resource` 身份，不应写死外链。

### 4.3 色彩与数值语义

- **所有 delta 都是同一个绿色 `#4fcb6f`**：`+4.2%`、`-18.2%`、`-7.1%`、`-0.04`、`-2 起` 全绿。
  指标方向（越高越好 / 越低越好）没有任何元数据，颜色只跟「有没有 delta」有关，跟正负、好坏都无关。
  财务屏若生成真数据，「收入 -12%」也会是绿色。
- **delta 没有单位约束**：`-4.4`、`+1`、`-0.04` 与 `+2.1%` 混排，读不出量级。
- **KPI 数值排版不统一**：`1.26 PUE` / `3,860 kW` / `9.2 万kWh` / `34.6%` / `7 条` / `12860 人次`
  —— 千分位、万位折算、单位是否紧贴数字，全靠模型随手写的字符串，没有数值格式层。
- 面板底色 `#10161e` 与画布 `#0b1020` 只差 ~2% 亮度，卡片边界在投影仪/拼接屏上基本不可见。

### 4.4 图表：从 0 归一，把有意义的差异压平

`agent-compose.ts` 的柱高 = `plotHeight × value / max`，永远从 0 起算：

- PUE 屏 7 根柱（1.3 / 1.3 / 1.3 / 1.3 / 1.3 / 1.3 / 1.2）**全部顶满**，视觉上「没有差异」，
  而这正是能耗监控最需要看的东西；
- 库存水位 92 / 88 / 84 / 79 / 71 / 93 同样几乎等高；
- 奇数柱 `#4c9df3`、偶数柱 `#2f6fb5` 交替着色，但没有任何分组语义——看起来像两种数据，实际只是下标奇偶；
- 负值直接让整份 spec 被拒（`readChartPoints` 要求 `raw >= 0`），所以「同比有正有负」这类最常见的经营屏永远走兜底。

### 4.5 排版可读性：一半文本在 12px

| 屏 | 文本节点 | <16px | 探针（默认无下限） | 探针 `--min-font-px 16` |
|---|---|---|---|---|
| 冷链 | 54 | 31 | 0 违规 | **31 违规** |
| 门诊 | 59 | 33 | 0 违规 | **33 违规** |
| 双十一 / 财务（兜底） | 36 | 17 | 0 违规 | — |

违规项全是柱顶数值与 X 轴标签（12px）与页脚（14px）。1920 画布投影到 1366 屏是 0.71 倍，12px 实际渲染 8.5px。
探针默认 `minFontPx = 0` 等于没开这项检查；`fit_resolution` 也不感知字号。
**「最小可读字号」在整条链路里没有任何一处是硬约束。**

其他排版细节：单位与数字之间没有间距（`86.4%`、`3.8小时`、`27条` 视觉粘连）；标题 46px 在 1920 宽画布上偏小，
与副标题 20px 只差一层；X 轴标签靠 `fitLabel` 按「汉字 1 字宽」估算截断，短标签没问题，长站点名（「会展中心」）会贴到相邻柱。

### 4.6 幽灵态：新旧两份一起画

DOM 证据（单组件提案，「字号 64」）：

```text
[data-base-screen-component-id=agent-title]  46px / 700  ← 内容层（旧）
[data-base-screen-component-id=agent-title]  64px / 700  ← .canvas-ghost（opacity 0.72）
```

两层都在、都可见，`opacity 0.72` 让新字叠在旧字上面 → 文字发虚、加粗变细、字号变化看不出边界。
整屏候选时更糟：旧标题「销售运营大屏」与新标题「全国仓储履约监控」重叠成一行乱码，
KPI 卡里「CPU 使用率 39.96%」和新指标「库存水位 86.4%」压在同一位置。

「对比预览」按钮点击后，DOM 唯一变化是 `.canvas-ghost { display: none }`——
名字叫对比，实际是「关掉预览」。没有分栏、没有高亮、没有差异标签。

### 4.7 反馈层的三处「说了不做 / 做了不说」

1. **数值意图只回显不执行**：输入「字号改成 64」，状态栏显示「已交给面板 · 未调用模型（字号 64）」，
   但右栏没切到检查器、没有聚焦字号、文档字体仍是 40。用户被告知「已交给面板」，面板里什么都没有。
2. **英文技术错误直出**：「topic must be shorter than or equal to 120 characters」+ 一个必然失败的重试按钮；
   输入框没有 `maxlength`，也没提示「还差 3 个字」。
3. **`submitChangeProposal` 拒绝时 `diagnostics: []`**：传 `dataValue` patch 被拒（`style` patch 正常通过），
   返回 `{ ok: false, diagnostics: [] }`，宿主无法知道原因。

### 4.8 产物污染

- 页脚写死了「生成自示例智能体 · 模型输出 · 布局由宿主编译，**未写入设计器历史**」。
  这句话是给验证者看的，却画在成品大屏上；而且采纳之后它已经在历史里，这句话变成了假话。
- 宿主查看页的 `.viewer-bar`（数据源在线 / 模拟告警 / 解除告警 / 时间 / 全屏 / 返回列表）悬浮在画布右下角，
  压住最后一块内容；1366×768 下占屏更明显。演示按钮混进成品视图。

### 4.9 图层与命名

77 个组件全部平铺（`maxDepth = 0`），名字是 `柱 × 13`、`柱值 × 13`、`X 轴 × 13`、`列表项 × 5`、`指标卡 × 4`。
图层树 77 行无分组、无重名区分，选不中想要的那一个。同一份数据在图层里也无法折叠。

## 5. 缺口清单

### P0（阻断「可用」）

| # | 缺口 | 证据 | 影响 | 方向 |
|---|---|---|---|---|
| 1 | 幽灵草案新旧叠加，评审面不可读 | 双份标题 DOM（46/64px）、整屏候选文字重叠截图 | 用户无法判断生成结果 | 替换型单元隐藏旧内容或去色；单组件单元只画新、旧内容降为轮廓 |

- 数值格式层缺失（千分位 / 万位 / 单位间距）——应统一格式化，而不是让模型写字面量。
- 标题字号 46px 偏小、层级弱；面板边界亮度差 2%。

## 6. 建议的修复顺序

1. **先把「采纳」做成安全的**（P0-1/P0-2）：整屏替换收敛成 1 个单元；或保留 76 个新增但禁止「先删」的中间态。
   验收：只采纳删除单元时文档仍完整，或该单元根本不可单独采纳。
2. **再让评审面可信**（P0-1/P1-7）：幽灵层只画变化、旧内容降透明度或描边；「对比预览」要么做成真正的并排 diff，要么改名「隐藏预览」。
3. **图片走宿主资源**（P0-3）：编译期改 `host-resource`，加载失败有底板；这条同时把 ADR-0089 的偏离补回来。
4. **兜底改成「空结构」**（P0-4）：宁可给一张「待生成」的骨架，也不要给一套像真的假数。
5. **可读性硬约束**（P0-5）：编译器提到 16px 起；`probe` 默认 `min-font-px 16`；引擎守卫接字号判定。
6. 版式按内容分配（P1-8）：图片/清单窄栏，图表宽栏；面板高度吃满到页脚上方。
7. 图表引入值域与基线（P1-9）：PUE 这类指标用「同色系深浅 + 基线」，不要从 0 归一；负值允许存在。
8. 语义色（P1-10）：KPI 增加 `direction: up-good | down-good | neutral` 与单位字段，颜色和格式由编译器决定。
9. 数值意图要么真回填面板，要么把文案改成「请在检查器里修改字号」（P1-11）。
10. 输入侧：`maxlength = 120` + 中文提示 + 去掉不可恢复的「重试」（P1-12）。

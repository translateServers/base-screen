# XJDataHub 落地方向说明

本页只给原则性建议，不替 XJ 规定具体实现。Base Screen 只负责规范快照、Skill 生成与验证；
XJ 的在线运行方式、后端、权限、通知和部署设计留在 XJ 仓库决定。

## 在线物料 MCP 方向

- XJ 可在自己的物料平台上实现远程 Streamable HTTP MCP；大屏聊天使用查询/配置校验，物料
  工作台使用创作上下文、模板和候选校验。
- MCP 与快照 exporter 读取同一权威物料目录，在 HTTP 边界完成用户、租户和权限校验，并记录
  变更通知与审计事件。
- 实际物料包继续由 XJ 审核、部署和加载；线上不执行仓库 Skill 的 Node 脚本，也不执行 MCP
  返回的模板文本。

## XJ 如何输出聚合快照

- 提供一份只读、脱敏、稳定排序的聚合快照来源，由 XJ 导出器写成 Base Screen 单文件快照
  （`BASE_SCREEN_HOST_SKILL_SNAPSHOT_FILE`）。
- 快照只含目录元数据：物料 manifest、资源类型、数据集描述与参数、组件索引、设计/物料规范、
  provenance 分类。不含凭据、连接信息、私有记录、可执行内容或远程模块地址。
- 日常同步默认读取共享测试环境；凭据仅存放在本地忽略配置或 CI secret，工具包不存储。

## 测试环境与凭证的大致要求

- 只读聚合接口：列出审批通过（approved/enabled）的物料与数据集目录。
- 稳定性：重复导出结果一致，不依赖时间戳或请求 ID。
- 权限：快照不携带任何授权语义；线上真实取数必须按当前用户权限实时查询，不能把共享测试
  快照当作授权目录。

## 在线 Skill 与本地 Skill 如何共用同一份元数据

- 本地两个业务 Skill（`design-<hostId>-screens`、`create-<hostId>-material`）与 XJ 站内大屏
  设计/物料创作消费同一份规范快照，保证身份、参数、字段一致。
- 本地 Skill 是离线确定性快照，用于 CI 验证与开发者工作流；站内交互（聊天、保存确认、
  物料工作台）由 XJ 实现，可复用同一快照来源。

## XJ 自己负责的权限、审核、发布和线上交互

- 线上物料或数据集目录变化后提示维护者并记录审计事件；由维护者执行同步、审查差异并合并，
  不自动修改生产。
- 大屏设计适合接入 XJ 聊天与保存确认链；物料创建适合复用现有物料工作台和草稿发布链。
- 线上 Skill 随 XJ 应用发布激活和回滚，不执行仓库 Skill 中的 Node 脚本，也不要求 Base
  Screen 管理 XJ 的运行时发布。

## 推荐的接入验收清单

- [ ] 聚合快照只读、脱敏、稳定排序，能在共享测试环境导出。
- [ ] 导出脚本把快照写入 `BASE_SCREEN_HOST_SKILL_SNAPSHOT_FILE`，且失败时非零退出。
- [ ] 接入命令执行成功，`.agents/skills` 只出现两个业务 Skill。
- [ ] `pnpm base-screen:skills verify` 在无凭据的 CI 环境通过。
- [ ] `check-remote` 能报告线上目录漂移，且不写文件。
- [ ] 线上真实取数始终按当前用户权限查询，快照不被当作授权目录。
- [ ] 目录变化走"提示维护者 → 审查差异 → 合并发布"流程，并记录审计事件。

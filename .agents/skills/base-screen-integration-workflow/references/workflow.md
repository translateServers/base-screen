# 跨仓工作流规范

本文件由 Base Screen 唯一维护，随开发 Skill 受管复制到 xjdatahub。宿主消费映射与执行命令由宿主维护；
业务生成 Skill、应用运行时快照和本开发 Skill 各自独立。当前实现仅运行本地开发任务，没有部署操作。

## 入口与信息所有权

两边的 pnpm integration 指向本 Skill 的 scripts/workflow.mjs。角色配置、上游能力索引、宿主消费映射、
实际消费快照与工具副本摘要保存在各自 .base-screen 目录。

能力索引是导航和边界说明，公开代码、已接受决策与实际验证提供证据；消费快照绑定产物输入摘要。
上游当前 checkout 的能力与宿主实际包能力分别显示。文档更新不代表运行时包已升级。
语义变更要更新相关能力与消费映射；脚本验证引用和来源，不自动判断自然语言正确性。

根目录优先级为 --base/--host、环境变量 XJ_BASE_SCREEN_DIR/BASE_SCREEN_HOST_DIR、本仓相邻目录配置。
受管配置只保存相对定位，不保存凭据或生产地址。
首次在供应商根执行 pnpm integration bootstrap --host <宿主目录>。重复执行不改写相同内容，
未知或被手改的受管 Skill 拒绝覆盖。Base Screen 的 .agents 忽略例外只覆盖本 Skill。

## 命令与任务

| 命令 | 用途 |
| --- | --- |
| bootstrap --host <目录> | 安装/更新受管 Skill、配置与 package script |
| status [--check] [--json] | 来源、漂移、能力和未完成任务；check 失败时非零退出 |
| context <能力,能力> [--json] | 最小上下文与待设计提案 |
| begin <任务> --capability <能力,能力> | 在当前仓库创建任务；同名任务恢复，不覆盖基线 |
| begin <任务> --route <归属> --decision <结论> | 更新边界，也可更新 goal、next、spec、upstream、downstream |
| sync --task <任务> [--profile focused] | 默认交付检查后同步，仅知识变化时不打包 |
| sync --task <任务> --recover | 审查日志后恢复中断事务，再继续 |
| verify --task <任务> --profile focused或delivery | 执行检查并保存证据 |
| finish --task <任务> | 校验阶段、同步状态和最新证据后关闭 |

归属只有 host、upstream、both、needs-info；阶段为 pending、complete、not-needed。
上游实现、下游接入与联合验收分别记录，sync 不替代实现验收。
普通任务使用本地记录，中大型任务通过 spec 引用既有规格；不维护两份完整需求。
已关闭任务不复用标识承接新需求。

## 同步事务

先检查，再验证、构建和打包同一上游工作树。包输入无变化则不安装或打包；仅知识变化时只更新上下文。
缺少来源记录时报告未登记，首次重新打包建立来源，不猜测旧包提交。
SOURCE.json 记录提交、工作树指纹、脏状态、包、锁文件、衍生文件和上下文快照摘要。包名保持当前固定名称。
允许本地未提交源码联调，来源如实记为 dirty，不自动取得发布资格。

受管路径由宿主适配器声明。已有修改只有与成功来源记录吻合时才可归因于之前的同步；
未登记、漂移的已有修改以及打包期间目标变化都不自动覆盖。
替换前保存备份和事务记录；构建/打包失败不更新宿主，后续失败恢复文件并以原锁修复依赖。
中断恢复要求当前内容与日志吻合，否则保留现场并报告冲突。依赖修复失败阻止关闭任务。
安装缓存不做字节回滚。

在线目录刷新沿用已有显式命令。离线同步只核验已提交静态快照，不证明在线目录 freshness。

## 验证和输出

focused 使用能力对应检查；delivery 执行适用的上游 verify:m0、宿主一致性/Skill/知识检查、单测与构建。
浏览器或后端行为变化时，在宿主消费映射 delivery 中登记相应本仓命令后执行，不能以跳过代替验收。
适配器只声明操作 ID、工具与 argv，不接收任意 shell 文本。

成功缓存绑定源码、锁文件、Node/包管理器环境、命令及产物来源；变化即失效。
失败/跳过不产生成功记录，在线检查不命中本地缓存，CI 独立执行。verify:m0 格式化后的输入是最终依据。
日志和任务保存在忽略目录，摘要最多 4,000 字符，超出时提供本地完整报告入口。

## 当前待设计方向

event-driven-alarm-style 提案追踪事件驱动告警样式替代。
styleRules 与 conditionalStylePort 仍存在，Designer 内建条件样式编辑区已移除。
后续独立设计事件视觉状态、初始恢复、幂等/乱序、告警解除及旧文档处理；本工作流不授权删除契约。
